## Open findings

### AUD-004-API001 · Strict file metadata accessors return portable payload writers (Low)

Blocks the agreed strict-mode release under AUD-002-SEC002.

Start with a strict file containing the four public bytes “demo”. Pass ordinary slices to reader.header().file_into(...) and facts.facts().files(...). Both chains compile and produce the expected file in the Linux fixture. header() returns &crate::Header. Its file_into takes an ordinary mutable slice and can write to a Vec. The returned crate::SetFacts similarly exposes files. The accessor itself reads only public metadata.

A caller can accidentally use ordinary destination memory or ordinary stack computation for the next operation. A new input or destination must be provided. No contents are disclosed merely by reading a header.

Return strict wrappers or a metadata-only view from ordinary getters. Provide an explicit as_portable() for callers who want the root writers. Preserve direct access to index, length and other public fields. Compile-fail test for a Vec destination on the natural reader/header chain. Add a positive test for protected storage and for an explicit portable opt-in.

Source and tests — src/strict/files.rs:48,83,115,181; src/file/header.rs:155,186,202; src/file/writing.rs:22. [Public API fixture](AUD-004-harnesses/public-api.rs)

### AUD-004-DOC001 · The Windows and WebAssembly refusal statement includes metadata-only calls (Low)

Documentation correction.

Compare the Windows test with the platform paragraph. The test unwraps Code::new and sources successfully, then expects Unprotected from encode and build. The headline claims every strict call refuses. Pure geometry and header inspection can succeed. The payload guard refuses on Windows and WASM. Cross-compilation passed; this distinction follows directly from the implementations.

Users could incorrectly treat successful construction as proof that payload operations are supported, or skip metadata display unnecessarily.

Say that operations which process payload bytes require the admitted stack. Give Code::new and encode as examples. Align the platform paragraph and test name/comment. Check wording against tests/suite/strict_elsewhere.rs and the platform-independent constructors. During native CI run both the metadata and refusal assertions.

Source and tests — README.md:237,296; docs/TECHNICAL.md:277,283; src/strict/codes.rs:19,88; tests/suite/strict_elsewhere.rs:10,17.

### AUD-004-DOC002 · Comparing correction entries does not establish complete plan equality (Low)

Documentation correction.

The unit test constructs two lists with identical edits and distinct input fingerprints. Their entries agree although == returns false. The test passed in both allocating Linux profiles. == reads the private binding and all used record bytes on the calling thread. get and strict::values expose positions and values but cannot compare the private binding. The audit index also says that only values reads those words.

A caller treating edit comparison as full equality could conflate plans for different inputs. A caller using ordinary == for protected plans can process word bytes on its own stack. apply still independently validates its binding.

Narrow the register sentence to location inspection. Document the extra fingerprint in the distinction between equality of edits and equality of complete plans. If callers need full protected equality, expose a helper that checks both plans and returns only a bool. Use the existing same-edits/different-binding case for any strict equality helper. Check refusal if either plan or the required stack lacks protection.

Source and tests — docs/audits/README.md:61; src/correct/changes.rs:109,207,324; src/strict/codes.rs:223.

## Scope limits

- Native execution here covers Linux x86-64 only. Windows GNU and macOS ARM were cross-linted, WebAssembly was compile-checked. No native run on Windows, either Apple mobile/desktop target, Android or Linux ARM64 for this uncommitted snapshot was observed here. The separate prior AUD-002-SEC001 native acceptance requirement remains open outside Linux x86-64.
- The five fuzz campaigns are retained author evidence from before the final freeze. Their logs and counts were inspected and copied. They do not identify the product fingerprint internally. They were not replayed by this audit and are not evidence of all strict stack paths.
- Each Rust profile leaves the opt-in exhaustive large-field proof ignored. The SHA-256 length boundary was verified using a descriptor test and control flow. The 32-bit empty-batch ordering was reviewed statically. Neither multi-gigabyte case was allocated.
- Machine-code evidence is specific to the pinned toolchain and Linux x86-64 build. It covers the metadata getter, not all optimization profiles, CPUs, compiler-created copies, registers or caller post-processing.
- The Apple policy asks the caller to confirm whole-process dump policy. Fork is a caller constraint during strict work. The audit does not establish resistance to an untrusted kernel, hibernation or secrets intentionally copied by application code.
- This is a remediation audit of the frozen sources. A release package, new CI run or downstream update is not part of its evidence. The manifest still sets publish = false.
