### AUD-008-BLD001 — The final MDS boundary probe does not assert its refusal

**Location:** `docs/audits/AUD-006-harnesses/codes/src/bin/mds.rs:208-213`.

**Reproduction:** Inspect the q+1-shard case: more appends shard index 0 to all q indexes; code.rebuild(&more, &[0]).err() is only interpolated into println!. Follow finish() and the fail() counter in src/lib.rs.

**Expected:** The probe fails when this invalid repeated-index set succeeds or returns an unexpected error.

**Observed:** Unexpected Ok becomes None and is printed; no fail/assert is reached for this case. Ordinary oracle mismatch branches now correctly call fail(). Retained actual runs print Some(Repeated), consistent with current production checks.

**Impact:** This retained regression probe cannot detect a boundary regression at its final check. No production acceptance bug was demonstrated; separate suite assertions cover repeated inputs.

**Evidence and challenge:** Static control-flow review independently challenged by the runtime and release reviewers; mds.rs:209-213 and Code input validation. This branch was unchanged by 23968f4.

**Recommended fix:** Assert the expected CodeError::Repeated result at this boundary, using the harness failure mechanism or an assertion.

**Required verification:** Run the normal probe, then a focused negative control of this exact final result; the normal run must pass and unexpected success/wrong error must fail.

### AUD-008-BLD002 — Audited commits retain non-UTC author and committer timestamps

**Location:** `Git commit metadata: 23968f4 and 15643f2`, `AGENTS.md:3`.

**Reproduction:** Read the author and committer headers of each audited commit with git cat-file. Compare only whether their timezone suffix is +0000; do not publish the actual suffix or identity.

**Expected:** Both timestamps use UTC under the workspace privacy rule incorporated by repository AGENTS.md.

**Observed:** Both author and committer timestamps of both audited commits are non-UTC. The predecessor b16c64f has the same issue. SSH signature headers are present.

**Impact:** Publishing these objects also publishes local timezone information and violates the explicit workspace commit policy. This is not a runtime or cryptographic defect.

**Evidence and challenge:** Independent release review of both immutable commit objects; repository AGENTS.md incorporates workspace AGENTS.md lines 64-65. Actual offsets are intentionally omitted.

**Recommended fix:** Set UTC for future signed commits. Decide the treatment of already signed, unpushed objects before publication; do not silently rewrite the snapshots this audit names.

**Required verification:** Check author and committer UTC booleans and signature presence for every object proposed for publication. Any replacement snapshot needs its own identity and verification.

### AUD-008-DOC001 — The timing description omits the zero-inverse exception

**Location:** `docs/TECHNICAL.md:152`, `src/field/gf65536.rs:28`, `src/field/binary.rs:2-4`.

**Reproduction:** Compare the unconditional single-operation branchlessness sentence with inverse(0) paths and the field-module comments. GF65536 skips its final multiplications when its norm has no inverse.

**Expected:** The guide qualifies inversion claims to nonzero operands and states that zero is distinguished as having no inverse, within the inspected compiler/platform scope.

**Observed:** The restored guide says single multiplication and inversion avoid operand branches without that exception; source comments explicitly exempt zero.

**Impact:** Readers receive a broader timing guarantee than the implementation and retained assembly review establish. These inverse helpers are private and decoder error-dependent timing is already disclosed; no new exploitable leak was established.

**Evidence and challenge:** Static source/document comparison, independently challenged by release reviewer. This paragraph was restored by 23968f4.

**Recommended fix:** State the zero-inverse exception and retain the compiler-hint and measured-build limitations.

**Required verification:** Compare the revised guide with all four inverse implementations and the actual scope of timing/assembly evidence.

## Observations and limits

1. Full static coverage means all 166 tracked files and 182 named public operations were assigned and reviewed, not that every possible defect was found. The active working-tree AUD-007 reports/harness and audit register were additionally reviewed.
2. Protection integration, dependency requirements and archive integrity were reviewed; this is not a complete fresh audit of secret-protection-core or every transitive dependency.
3. Native execution is limited to Linux x86-64. No fresh ARM, macOS, Windows or WebAssembly runtime, Miri, sanitizer campaign, forced allocator-failure campaign, or all-compiler/optimization sweep was performed.
4. The timing gate is a coarse median-ratio regression detector, not a constant-time proof. Binary degree 10 represents the generic family; only inspected assembly establishes the observed instruction paths. black_box remains a best-effort hint; inverse zero rejection and error-dependent decoding remain outside the nonzero arithmetic claim.
5. Retained coverage has an exactly reproduced documented input fingerprint, matching per-file JSON and valid log/command hashes, but its historical runner did not capture contemporaneous before/after source manifests. Do not describe it as fresh or as cryptographic per-command source capture.
6. The retained new timing positive log was produced before removal of a redundant mut in the example. Its negative log lacks a mutation diff, source manifest and command record. Reported ratios 2.65/1.74 are consistent with the supplied explanation but not independently source-bound negative-control evidence.
7. Large-field proof and existing fuzz campaigns were reused because runtime algorithms, dependency locks, fuzz targets and proof checker are unchanged; no unnecessary full-cost replay was run. Fuzz uses alloc and small dimensions, not every strict/protection failure.
8. The recent retained RustSec scans have valid logs but no recorded advisory-database commit. Root had two allowed development-only warnings (instant and lru); it was not a warning-free scan.
9. No Actions run exists for either unpushed target at inspection time. No v0.1.1 package was published or matched to an attestation. SSH signatures are present, but local verification lacks an allowed-signers trust configuration; this is not an invalid-signature finding.
10. Several apply_cross refusal cases check the error without separately asserting unchanged output; equivalent production-suite refusal tests exist. Cyclic fuzz prose is broader than its actual nearest-codeword assertions. Neither established a new runtime defect.

The oracle-control observation is AUD-008-ARC001 in JSON. No remote run or published artifact was inferred from local success. No failed signature verification was interpreted as an invalid signature when the local trust configuration was missing.
