# AUD-002 · Pre-release audit of reed-solomon-core

**Decision: HOLD.** The reviewed source supports correct RS operations on the tested public fixtures. It does not meet a requirement that all secret-bearing calls must fail closed when protected storage is unavailable. Batch file serialization also has a potentially aborting allocation after it touches the caller’s outputs.

2026-11-15 UTC · 100 input files · 32 checklist entries · 26 findings (3 high, 5 medium, 18 low) · 6 release blockers.

Base commit `73771bfb62327c4eec540cc64c26d35c52cbf052`. Working-tree fingerprint `0d6de2c4d47fc219d5b24094ddd3103e5bdba8c952511bff1387fac6d821303f`. Seven new Rust files and all tracked changes are included. [Machine-readable findings, public operations, file hashes and commands](AUD-002-2026-11-15.json). ## Where secret bytes travel


| Stage | Observed boundary |
| --- | --- |
| Input | The application supplies slices. The codec cannot attest the storage behind them. Systematic shards contain plaintext by design. |
| Temporary working data | Owned decoder lists now use Numbers over Buffer. Native WorkArea allocation is best effort. SHA partial input and arithmetic tails have separate lifetimes. Process and stack protections are controlled by the host. |
| Result | Native Buffer exposes the OS status for its own pages. A result cannot attest freed temporary memory. Portable owned buffers and WASM linear storage remain possible. |
| Correction plan | The list itself can have protected pages. Its iterator returns copyable old and new symbols; apply uses this interface internally. Redacting Debug does not address these copies. |
| Failure and persistence | A returned late error can zero borrowed output. An abort can skip cleanup. _into accepts mapped destinations where writes may become visible before success. |
| Independently requested facilities | The complete protection crate is re-exported. The five upstream blockers belong to optional ClosedSecret/worker APIs. The ordinary codec uses WorkArea. |

## Findings


### AUD-002-SEC001 · Owned operations accept pages the OS did not lock

High · Release blocker.

WorkArea::new can succeed with a false lock status. Flags for a result do not attest earlier scratch allocations. Dump and fork exclusion are separate capabilities. A successful native encode or recovery can use pageable secret memory. No swap or dump disclosure was measured.

**Evidence**

`src/buffer/pages.rs:20`, `src/correct.rs:229`, `pin src/protect.rs:176`, `pin src/os/unix.rs:72`.

**Correction and verification**

Introduce one fallible strict allocation policy for all owned results and scratch. Specify required capabilities per OS and reject the operation before secret bytes enter an inadequate region. Normal allocation and policy-refusal tests for result and scratch on each supported platform; no partial output on refusal.

### AUD-002-SEC002 · Portable and caller-owned entry points have no secret-memory boundary

High · Release blocker.

The alloc-only path owns an ordinary Vec. Default WASM uses linear heap. Native protected builds still accept arbitrary input, output and scratch slices. agrees_in leaves generated bytes with the caller; _into may be backed by a file. A native protected result gives no assurance about the supplied seed, scratch or destination. Zeroization after use does not protect bytes during use.

**Evidence**

`Cargo.toml:11`, `src/buffer/heap.rs:8`, `src/code.rs:214`, `src/code.rs:253`, `src/cyclic/words.rs:150`, `src/file/set.rs:368`, `pin src/os.rs:299`.

**Correction and verification**

Expose a distinct strict entry point requiring protected storage for all secret-bearing inputs, outputs and scratch. Keep generic no_std methods available to public-data users. Reject unsupported targets for that entry point. Compile-time API checks and native/portable/WASM contract tests; no unchecked path from a strict operation into a portable operation.

### AUD-002-SEC003 · Correction records export secret symbols by value

Medium · Release blocker.

Change is Copy with public was/becomes fields and manual Zeroize. Iteration reconstructs records; apply internally uses this interface too. Debug omits the values. One corrected symbol can represent one mnemonic word. Wiping one returned record cannot wipe earlier copies.

**Evidence**

`src/correct/plan.rs:34`, `src/correct/plan.rs:158`, `src/correct/changes.rs:46`, `src/correct/changes.rs:119`.

**Correction and verification**

In the secret profile use borrowed protected records or a protected output with scoped inspection; keep a separate position-only result. Avoid copying plaintext records during apply. Inspect every iterator and apply path, verify that the strict record cannot implement Copy or be returned by value; test with public synthetic words.

### AUD-002-SEC004 · Transient shard bytes and SHA input state have no enforced protected placement

Medium · Release blocker.

The arithmetic tail copies up to seven bytes to a local array and materializes a product. The optional SHA path buffers its partial block outside WorkArea. RustCrypto enables zeroization on Drop. Protected stack and process isolation are caller choices. RAM protection of a Buffer alone cannot cover these temporaries. Actual spills, swap and forensic recoverability were not measured.

**Evidence**

`src/field/lanes.rs:61`, `src/file/facts.rs:19`, `docs/TECHNICAL.md:266`, `block-buffer 0.12.1 src/lib.rs:203,433`.

**Correction and verification**

Remove avoidable tail copies or erase them, run required secret computations within an attested protected stack/process boundary, and explicitly state limits for registers, compiler and host. Review emitted code on supported targets and audit the protected entry point end to end, including hashing, errors, cancellation and callbacks.

### AUD-002-SEC005 · Public protect re-export pins a revision with five upstream release blockers

High · Release blocker.

Both lockfiles pin fb2a6d345caf8eb58097f013f12e43985402150f. Upstream documented five blockers for this revision involving ClosedSecret after fork and worker launch, termination and isolation. Fixes and follow-ups are on later commits. Consumers using the re-exported operations can reach the affected facilities. Ordinary RS encoding calls WorkArea; no path from the encoder into those five facilities was found.

**Evidence**

`Cargo.toml:31`, `Cargo.lock:263`, `fuzz/Cargo.lock:202`, `src/lib.rs:46`, `upstream AUD-014-SEC001 through SEC005 and AUD-015`.

**Correction and verification**

Select a reviewed fixed immutable upstream revision, update both lockfiles and narrow the re-export to the facilities the crate needs. Verify upstream fix ancestry and platform evidence for the selected hash, compare both lockfiles and rerun native integration gates.

### AUD-002-SEC006 · Correction timing claim is stronger than the implementation

Low · Open.

A discrepancy may cancel to zero depending on error magnitudes. The decoder branches on this result; the narrower scaling-kernel statement survives review. Callers cannot assume correction timing discloses only the positions and count. No timing recovery was demonstrated.

**Evidence**

`docs/TECHNICAL.md:251`, `src/recurrence.rs:22`, `src/correct.rs:682`.

**Correction and verification**

Limit the claim to the verified arithmetic kernel and explicitly document decoder data dependence. Documented timing model reconciled with all decoder branches.

### AUD-002-SEC007 · Vote metadata can survive a reallocating Vec growth

Low · Open.

Zeroizing wipes the current Vec allocation. A moving reallocation after insertion can leave an older allocation unwiped. Only metadata (disagreement positions and file numbers) is evidenced here.

**Evidence**

`src/file/set/vote.rs:272`, `src/file/set/vote.rs:408`, `src/file/set/shards.rs:27`, `docs/TECHNICAL.md:260`.

**Correction and verification**

Pre-reserve a checked upper bound before filling, or explicitly clear old storage during growth. Test growing votes with public data and review reservation bounds.

### AUD-002-API001 · A correction plan does not bind the complete input reading

Medium · Open.

Only positions present in Changes, their old values and the replacement ranges are verified. Unlisted symbols and shard identity are not bound. An intervening edit elsewhere can leave the output inconsistent while apply returns success.

**Evidence**

`docs/TECHNICAL.md:184`, `src/correct/plan.rs:158`, `tests/suite/cyclic.rs:440`.

**Correction and verification**

Require replanning after any edit or bind a plan to the input and code parameters; distinguish hand-built change lists. Tests for changed unrelated symbols, reordered inputs, rejected stale plans and atomicity.

### AUD-002-API002 · Some Result-returning owned methods use infallible metadata allocations

Medium · Open.

collect into Vec and Vec::with_capacity can enter the global allocation error handler before the caller receives Result. Under memory pressure a host can terminate while correcting a backup.

**Evidence**

`src/code/owned.rs:46`, `src/code/owned.rs:107`, `src/correct.rs:69`, `src/correct/plan.rs:118`, `src/correct.rs:624`.

**Correction and verification**

Reuse the existing checked reservation helper before filling these vectors. Review allocation closure across encode, rebuild, plan and correct; verify propagation using deterministic allocator tests.

### AUD-002-API003 · Batch write or repair can terminate after touching the output

Medium · Release blocker.

Stable sort_by_key may allocate a temporary Vec. When allocation fails its global error path bypasses the caller's Result and cleanup after headers were written. Existing file-backed outputs can be left partially written on process termination; no forced allocator failure was executed.

**Evidence**

`src/file/set/sink.rs:79`, `src/file/writing.rs:97`, `src/file/writing.rs:112`, `src/file/set.rs:504`.

**Correction and verification**

Use an allocation-free unstable sort keyed on both slot and original ordinal, or prepare all necessary fallible scratch before writing. Cover duplicate targets, ordering and typed late failure in writer and repair; verify cleanup at the actual API.

### AUD-002-API004 · Self-test can abort while constructing expected corrections

Low · Open.

FromIterator<Change> invokes the global allocation error handler on failure, including a refused WorkArea mapping. An application using the startup check may terminate.

**Evidence**

`src/self_test.rs:338`, `src/correct/changes.rs:169`.

**Correction and verification**

Compare the returned plan with a fixed public array and reuse it for apply. Verify self-test status for unavailable scratch.

### AUD-002-API005 · agrees_in reports the threshold for a fixed scratch-length failure

Low · Open.

A short comparison buffer triggers an error message about the number of shards. At a small threshold the recovery advice is incorrect.

**Evidence**

`src/code.rs:59`, `src/code.rs:261`.

**Correction and verification**

Report the required size or add a distinct comparison-scratch error. Test error text for a 255-byte buffer and a threshold of two.

### AUD-002-API006 · FileError::Memory describes the wrong outcome of a late failure

Low · Open.

The variant promises no write; files_into can zero every output after a late refusal. A caller may wrongly expect its old output to be preserved.

**Evidence**

`src/file.rs:54`, `src/file/writing.rs:60`.

**Correction and verification**

Document the different early and late guarantees for each operation. Check the docs against existing in-place outcome tests.

### AUD-002-API007 · The digest-bearing format accepts lengths beyond the SHA-256 standard

Low · Open.

The shape checks do not specifically reject digest-bearing inputs of 2^61 bytes or more when the geometry passes. A format reader can accept a descriptor outside the standard hash input domain; primarily a metadata interoperability issue.

**Evidence**

`src/file/facts.rs:64`, `src/file/facts.rs:203`, `FIPS 180-4 §6.2`.

**Correction and verification**

Reject such lengths when the digest is present or specify a different versioned mechanism. Check the boundary at 2^61 minus one and 2^61 using metadata only.

### AUD-002-ARC001 · Cyclic correction acquires two search workspaces per nontrivial call

Low · Open.

Each pass allocates again. Second-pass allocations occur before writes; atomicity was not disproved. Extra mappings and a second opportunity for a Memory result. Peak space need not double.

**Evidence**

`src/cyclic/owned.rs:134`, `src/cyclic/owned.rs:224`, `docs/TECHNICAL.md:200`.

**Correction and verification**

Reuse scratch across passes or document the allocation count accurately. Review allocation count and atomicity in a correction requiring two passes.

### AUD-002-ARC002 · The file-format self-test bypasses the public no-alloc writer

Low · Open.

The fixture chains sections itself, while the public writer writes offsets. Integration tests cover the writer separately. A writer regression may leave startup self-test green.

**Evidence**

`src/file.rs:134`, `src/file/header.rs:202`, `tests/suite/files.rs:129`.

**Correction and verification**

Write the fixed public vector with file_into into a fixed array. Test that the self-test compares every byte of the real writer output.

### AUD-002-FUN001 · Empty batch writes still perform avoidable memory and preparation work

Low · Open.

The writer prepares blocks and comparison scratch despite having no spare holders to compare, and even when no outputs are requested. Empty requests can return avoidable Memory failures and cost work.

**Evidence**

`src/file/writing.rs:126`, `src/file/writing.rs:245`, `src/file/set.rs:727`, `tests/suite/sets.rs:171`.

WorkArea::new and best-effort Secret constructors can succeed without a lock. An already obtained slice is not rechecked on access after fork. WASM uses the heap. WER registration can require multiple blocks for a very large region. Misleading guidance when selecting platform protections.

## Observations, exclusions and challenges


- **AUD-002-SEC008 · File payloads and identifying digests can leave process memory.** The systematic files store plaintext fragments by design. CRC, majority voting and an unkeyed digest do not authenticate authors or encrypt a seed. Debug hides shard payloads but may show identifiers and digest metadata. A low-entropy message can be sensitive even as a digest.
- **AUD-002-SEC009 · A share in a caller mapping may be visible before final verification.** rebuild_into writes then verifies; a later returned error zeros the destination. A memory-mapped output is not a private transactional staging area. The caller must own the storage and control concurrent readers and persistence.
- **AUD-002-FUN002 · Recovery boundaries were supported by independent vectors and the exhaustive field check.** No arithmetic error was identified within the correction bound. Outside it, another valid codeword can be returned. Integrity of the original requires an independently trusted reference when authenticity matters.
- **AUD-002-BLD005 · The source candidate has no exact native release-matrix attestation.** The release target is a source crate with publish=false and a draft file format. Dirty changes and untracked modules are absent from the base commit. Older hosted matrix runs do not attest these exact bytes.

The checked allocation for Numbers and owned short decoder lists supersedes the older observation of ordinary heap storage of these lists. SHA state and the partial-block buffer clear on normal drop. The public field coefficients used for scaling do not depend on the secret. A second cyclic search allocation occurs before that pass writes. No evidence established a decoder timing attack, an actual OS disclosure, or unprotected plaintext throughout every call.

## Scope and handoff


The default rustdoc export table contains 46 exported names and 106 explicit public inherent methods. The JSON identifies these methods, local trait implementations and all 100 baseline files. The five review assignments covered coding, file persistence, memory, build evidence and independent challenge. The command ledger separates newly run checks from retained evidence.

- Fresh runtime evidence is for Linux x86-64 with public inputs. Target compilation does not execute the native Windows, Apple, ARM, bare-metal or browser memory backends. No hosted CI was dispatched for the dirty candidate.
- This is a defensive source and contract review plus ordinary repo tests. No collection of actual secrets, forced failures in a system allocator, swap/dump forensics, timing attack or proof of emitted-code zeroization was performed. Rust source placement cannot establish absence of compiler spills.
- Fuzz runs are bounded smoke checks. The calls scratch-size blind spot persists. Existing external vectors cover specific parameterizations. No mathematical or exhaustive security proof is claimed.
- Upstream cross-platform audit outcomes are retained evidence for their own pinned objects. No whole-consumer MnemoCode or MHFE audit, registry publication or deployed binary attestation is included.
- Public API inventory lists crate-level exports, locally implemented methods and explicit local trait implementations at the default feature union. External re-exports are named with their dependency version and boundary; their entire dependency graph was not re-audited.

The correction-contract harness exercised two further cases. Editing an unlisted symbol after planning gave success from apply and false from agrees. The format constructor accepted a digest descriptor for exactly 2^61 bytes without allocating any data.

Before release, implement and test the strict entry point and file cleanup changes, then bind verification to an immutable commit.
