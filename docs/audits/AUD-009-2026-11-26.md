## Review evidence

### Scope and methodology

The [file inventory](AUD-009-files.json) lists all 181 snapshot inputs. Against the retained AUD-008 inventory, 137 are byte-identical, 29 changed, and 15 are newly inventoried. Retained detailed evidence is credited on unchanged bytes where its scope matches. Current variant review revisited source, test, fixture, fuzz, example, documentation, workflow and package groups. Historical audit artifacts retain their original dependency graph and result scope.

The [public-surface ledger](AUD-009-api.json) lists 182 named operations and the 35 direct ordinary data-call wrappers, with supplemental trait and re-export boundaries. The exact source also has 30 explicit strict data operations. Independent completeness review reconciled prior paths, exported signatures, new ordinary wrappers and the role of trait methods.

The code review follows point and cyclic encoding/decoding, all named field and configurable field implementations, coordinate and capacity limits, the plan identity and two-pass write boundary, v1 file envelopes, CRC, truncated inputs, quorum and work accounting, error redaction, and the source-to-dependency memory paths. Unchanged correctness algorithms were compared with their prior evidence and current tests. The library delegates OS memory operations to SPC. It accepts payloads through caller-provided memory and has no UI, file/network transport, wallet derivation, provider or transaction surface.

There are 35 explicit calls to `crate::cleared`. The outermost native call with protect enabled invokes the SPC window. Inner calls use the existing thread-local scope. The strict scope is entered inside the successfully admitted protected thread and ordinary wrappers there leave cleanup to SPC. `FileSet::without` enters `cleared` on the ordinary path and runs under `strict::run` on the strict path. Standalone `==` is independently reachable and has the omissions in SEC001.

The Linux release unit binary contains a `memset` of `0x20000` zero bytes after stack probing. The strict release binary retains length-driven zero-writing calls in both `Pages::wipe_any` and `WorkArea::drop`. The dedicated stack path supplies a page-rounded 512 KiB area. The current routine tests exercise a synthetic stack marker with a positive control and the TLS scope lifecycle, independently of these disassembly observations. The TLS test does not count physical writes, and the marker scan is 112 KiB. Compiled code and upstream source establish the mechanism on this build. The test does not measure every frame or returned copy.

There is one current locked SPC package. Both live lockfiles record the same package checksum. The registry cache and retained release archive have SHA-256 `27c89c8b0707b953e159a053fbc22e240ca221010229b5759803c6d314548ef7`. The package records `6d7fdefa21081e13616ca4927d5ff38394452092`, the local SPC v0.2.0 tag target. A reviewer compared all 25 packaged Rust source files with the registry extraction and tagged source. The retained signed checksum manifest passed a fresh detached PGP verification with the retained release public key. The archived build-attestation log available locally contains no verdict. This audit makes no new online attestation claim.

`src/buffer/pages.rs` calls SPC for memory and `src/stack.rs` routes to SPC for wiping. RSC has no separate native memory mapper, secure-thread implementation or stack-writing routine. Its own sealed admission, TLS nesting, allocator fallback, direct zeroization of select local objects and error-output clearing have separate purposes. Historical harnesses pinned to 0.1.1 remain frozen and are outside the current dependency graph.

#### AUD-009-SEC001 — Medium — Public equality operations bypass the promised ordinary stack clearing

- **Status** Open. Release-blocking flag is false. The failed ordinary audit checks are recorded independently of this flag.
- **Evidence and inspection** `src/buffer.rs:136–145`, `src/correct/changes.rs:208–223`, `src/file/reading.rs:44–54`, `src/correct/plan.rs:62–77`, `src/file/set.rs:74–86`, `src/strict/files.rs:193–196`, `docs/API.md:29`.
- **Expected** The documented ordinary protect-feature guarantee covers operations that inspect payload bytes, including public trait calls unless expressly scoped out.
- **Observed** Standalone Buffer::eq and Changes::eq read the operands directly, and derived Block::eq compares Intact byte slices. Plan and Rebuilt inherit the underlying equality. The call paths invoke no cleared wrapper. Equality invoked after a strict method returns runs where the caller invokes it.
- **Impact** The caller can compare secret-bearing values without the advertised cleanup. Source confirms that the cleanup routine is bypassed. Compiler spills, readable residue and recovery of actual secrets were not established.
- **Correction** Cover library-owned payload comparisons with the ordinary policy, and document the scope of caller-side comparisons and the result types returned from strict calls.
- **Verification** Review explicit and derived PartialEq/Eq implementations and the strict result types, and check representative ordinary call boundaries in optimized supported builds.

### Assessment and limitations

- The full native/mobile matrix is pending: obtain candidate-matched AArch64/Linux, macOS, Windows, Android and iOS runtime evidence. The target table distinguishes unavailable native, lint-only and unsupported rows. The local WABT probe is not browser end-to-end.
- Review of raw optimized output confirms selected writes on Linux/x86-64 only. It does not establish the deepest stack frame, all compiled call sites and platforms, register erasure, caller-owned data, or behavior after abrupt process termination.
- Full-suite Miri was narrowed after the two-MiB-per-shard allocation regression exceeded the time cap while the machine took thermal pauses. The archived command and scoped reruns are recorded separately.
- The six targeted Miri runs exercised the same four checks for buffer alignment, lane arithmetic and file boundaries on x86-64, i686 and s390x under both strict provenance and Tree Borrows. This is interpreter evidence for the portable paths. The five libFuzzer targets ran with the address sanitizer. Each records elapsed time, actual mutations and edge counters. Separate cmin and source coverage attribution were not executed. Platform-independent allocator paths were sampled in Miri. Native OS-backed protection was tested directly on Linux x86-64 and i686.
- The current host lacks cargo-hack, cargo-careful and several native mobile and desktop runtimes. Target lint, dependency source/bans checks and OS runtime evidence are recorded separately.
- The ordinary audit does not repeat the ignored large-field proof or frozen high-cost historical probes. Their results remain bound to their earlier snapshots. No production line-coverage percentage was generated for the current snapshot.
- The 512 B/4 KiB/64 KiB and 2 microsecond figures are historical. Two retained separate stripe binaries differ in SHA-256. Their input/build records did not independently bind those figures to this snapshot. The earlier stale-mtime comparison is excluded.
- The SPC release archive, lockfile bytes, local tag object and detached PGP verification are separate from a fresh GitHub build-attestation verification for the audited RSC package. No RSC crate has been packaged, signed, or published by this audit.
- The supported matrix has no declared TARGETS.md. Linux 32-bit and big-endian analysis, WebAssembly and bare-metal runner distinctions were derived from support claims, CI, compiler configuration and V2.
