## Findings

### AUD-001-DOC001 — Low — The documents promise of a buffer's pages what not every system gives

- **Affected files:** `README.md`, `docs/TECHNICAL.md`, `CHANGELOG.md`, `Cargo.toml`, `src/buffer.rs`, `src/buffer/pages.rs`.
- **Evidence:** They say that a buffer is kept out of core dumps and of child processes. The protection crate gives both on Linux and Android, child processes only on macOS and iOS, error reports on Windows, and neither in WebAssembly, where a buffer is the allocator's memory. They do not say that the `protect` feature brings the standard library.
- **Reproduction:** Read the section Secrets in memory against the table of systems in secret-protection-core's technical description.
- **Expected:** The documents claim no more than each system gives (DOC-07).
- **Observed:** One sentence for every system.
- **Impact:** A reader on macOS, Windows or in a browser takes a dump of the process to hold no data of a buffer.
- **Recommended fix:** Say what each system gives, and that the feature needs the standard library.
- **Required verification:** The changed sentences against the protection crate's table.

### AUD-001-DOC002 — Low — No measured test coverage is published

- **Affected files:** `README.md`, `docs/`.
- **Evidence:** The README and docs/ give no line coverage, its platform, scope and command (DOC-09).
- **Reproduction:** Look for a coverage figure in README.md and docs/.
- **Expected:** The latest measured line coverage in the README, with the details in docs/.
- **Observed:** None.
- **Impact:** A reader cannot tell how much of the code the tests run.
- **Recommended fix:** Measure with cargo-llvm-cov and publish the figure and its record.
- **Required verification:** The record's counts against a run of the command it names.

### AUD-001-BLD001 — Low — The gates and the tests run on one machine only

- **Affected files:** `.github/workflows/`.
- **Evidence:** The repository has no workflow. With the `protect` feature the buffers are made by other system calls on macOS and Windows than on Linux, and no test of this crate had run there.
- **Reproduction:** List .github/ at the reviewed commit.
- **Expected:** The fast gates at every push, and the tests on each system the crate runs on natively.
- **Observed:** None of it runs outside the development machine.
- **Impact:** A break on another system or feature set shows only when a program is built there.
- **Recommended fix:** A CI workflow with the gates of AGENTS.md and the tests on Linux for AArch64, macOS and Windows, and the RustSec audit of Cargo.lock.
- **Required verification:** A green run on every system.

### AUD-001-ARC001 — Medium — A test holds 65,536 buffers at once and fails where the system allows fewer mappings

- **Affected files:** `tests/suite/oracle.rs`, `tests/suite/support.rs`.
- **Evidence:** `every_one_of_the_65536_shards_equals_reed_solomon_erasure` makes the whole set in one call. With `protect` every shard is a mapping of its own, so the call needs more than 65,536 mappings; Linux allows 65,530 by default.
- **Reproduction:** `cargo test` on a Linux system with `vm.max_map_count = 65530`, such as Debian 12 or RHEL 9.
- **Expected:** The tests pass on a system with the default limits.
- **Observed:** By reading: `CodeError::Memory` and a panic at `unwrap`; tests that correct at the same time could stop the binary. It passed on the development machine, which allows 1,048,576 mappings.
- **Impact:** The test suite fails on common systems and in containers on them.
- **Recommended fix:** Make the shards a few thousand at a time.
- **Required verification:** The test passes with the shards made in batches, and its expected bytes are unchanged.

### AUD-001-DOC003 — Low — Two examples in the README no longer compile

- **Affected files:** `README.md`.
- **Evidence:** `assert_eq!(*set.rebuild(None)?.data, data)` compares bytes with a reference to an array now that the data comes in a `Buffer`. The same lines in `tests/suite/examples.rs` were changed; the README was not.
- **Reproduction:** Compile the README's example of a set of files.
- **Expected:** The README's examples compile, as the tests that copy them do.
- **Observed:** Two `assert_eq!` lines without an implementation of `PartialEq` for their types.
- **Impact:** A reader who copies the example gets a compile error.
- **Recommended fix:** Compare with `*data`.
- **Required verification:** The README lines equal those of `tests/suite/examples.rs`.

### AUD-001-DOC004 — Low — The README names one dependency

- **Affected files:** `README.md`.
- **Evidence:** Its first paragraph says that the crate has one dependency, `sha2`, and works without an allocator. The default build also takes `zeroize` and `secret-protection-core`, which brings the standard library and its own dependencies.
- **Reproduction:** Read the first paragraph against Cargo.toml.
- **Expected:** The paragraph names the dependencies of the default build (DOC-07).
- **Observed:** One dependency named.
- **Impact:** A reader who wants few dependencies is misled.
- **Recommended fix:** Name the dependencies and say when the crate needs no allocator.
- **Required verification:** The paragraph against Cargo.toml.

### AUD-001-FUN001 — Low — A list of changes keeps a shard's place in sixteen bits

- **Affected files:** `src/correct/changes.rs`.
- **Evidence:** A record kept the shard's place in two bytes and saturated a larger one to 65,535, which is a real place in a set of GF(2^16).
- **Reproduction:** Collect `Change { shard: 70_000, .. }` into a `Changes` list and apply it to 65,536 shards whose last one holds the value the change names.
- **Expected:** `CodeError::Changes`, as for any place outside the shards.
- **Observed:** By reading: shard 65,535 is changed. Two lists with shards 70,000 and 65,535 also compare equal. A plan never makes such a change; only a list a program collects can hold one.
- **Impact:** A program that lists a wrong place gets another shard changed instead of a refusal.
- **Recommended fix:** Keep the shard's place in more bytes.
- **Required verification:** A unit test with a place above sixteen bits.

### AUD-001-API002 — Low — `Code::apply` checks one pass of an iterator and writes another

- **Affected files:** `src/correct/plan.rs`.
- **Evidence:** `apply` took any iterator that can be cloned, checked the changes on a clone and wrote them from the original. An iterator with shared state can give other changes the second time, and an owned `Vec<Change>` is copied whole by the clone, which is freed unwiped.
- **Reproduction:** Call `apply` with `iter::from_fn` over a `Cell`, or with `vec.into_iter()`.
- **Expected:** Exactly the changes checked are written, and no copy of them is left unwiped.
- **Observed:** By reading: unchecked changes can be written, with arithmetic that panics in a debug build, or nothing is written and the call succeeds.
- **Impact:** A program with such an iterator changes shards it did not check, or keeps an unwiped copy of symbols.
- **Recommended fix:** Take only a list the crate holds.
- **Required verification:** The signature and its callers.

### AUD-001-API003 — Low — A refused working memory stops the program

- **Affected files:** `src/correct.rs`, `src/correct/plan.rs`, `src/correct/changes.rs`, `src/buffer.rs`, `docs/TECHNICAL.md`.
- **Evidence:** `Code::correct`, `Code::plan` and a list of changes that grows called `handle_alloc_error` when a buffer was refused. With `protect` that happens at the system's limit on mappings, not only without memory, and the documents named only the `Memory` errors.
- **Reproduction:** Correct or plan while the process is at its limit on mappings.
- **Expected:** `CodeError::Memory`, which the crate already has.
- **Observed:** By reading: the process stops.
- **Impact:** A program that could have answered a refusal is ended instead.
- **Recommended fix:** Return `CodeError::Memory`.
- **Required verification:** No `handle_alloc_error` left on these paths; the documents name the calls.

### AUD-001-DOC005 — Low — `Code::correction_memory` is called an upper bound while pages round its largest part up

- **Affected files:** `src/correct.rs`, `README.md`.
- **Evidence:** With `protect` the syndromes take whole pages, and the figure counts the bytes asked for: with GF(2^8), 200 spare shards and long shards, 4,194,200 bytes are counted and 4,194,304 mapped.
- **Reproduction:** Compare the figure with the pages of the syndromes' buffer.
- **Expected:** The documents say what the figure counts.
- **Observed:** "At most" in the README and in the comment of `correct`.
- **Impact:** A program that budgets exactly to the figure is off by less than a page.
- **Recommended fix:** Round the figure up to a page, or say what it counts.
- **Required verification:** The changed comments and README line.

### AUD-001-API004 — Low — A buffer says only whether it is locked

- **Affected files:** `src/buffer.rs`, `docs/TECHNICAL.md`.
- **Evidence:** The protection crate also says whether pages are out of core dumps and out of child processes; `Buffer` did not pass that on. On Windows a process can keep only a limited number of blocks out of error reports, and locked pages still go into a hibernation image; the documents named neither.
- **Reproduction:** Look for `is_out_of_dumps` on `Buffer`; make more buffers than Windows registers.
- **Expected:** A program can ask what each buffer got, and the documents name both limits.
- **Observed:** One answer of three; neither limit named.
- **Impact:** A program on Windows that holds many buffers cannot tell which are left in error reports.
- **Recommended fix:** Pass the two answers on and name both limits.
- **Required verification:** The two methods and their unit test; the documents.

### AUD-001-ARC002 — Low — A vote makes a new buffer at each change of holders, and a list of changes starts with room for four

- **Affected files:** `src/file/set/vote.rs`, `src/correct/changes.rs`, `docs/TECHNICAL.md`.
- **Evidence:** Each time the shards that hold a block change, the vote drops its search and makes a new one, which with `protect` is a new work area: a handful of system calls and a wipe. A list of changes mapped and unmapped six times before it filled one page.
- **Reproduction:** A pile whose holders change at every block; a plan with a hundred changes.
- **Expected:** Costs that the documents name, and no remapping of a list inside one page.
- **Observed:** By reading, as described; the step limit counts the arithmetic, not the system calls.
- **Impact:** Slower votes on unusual piles and slower plans; no wrong answer.
- **Recommended fix:** Keep the syndromes' buffer between searches; start a list at a page.
- **Required verification:** The list's first room; the documents.

### AUD-001-ARC003 — Low — No test catches a merge that lists found symbols after the marked ones

- **Affected files:** `src/correct/plan.rs`, `tests/suite/plans.rs`, `docs/audits/AUD-001-harnesses/fuzz/fuzz_targets/plans.rs`.
- **Evidence:** The fixed cases and the self-test have the found symbol after every mark, the random test sorts before it compares, and the fuzz target says nothing about order or kind.
- **Reproduction:** Change the merge of found and marked runs to put the marked run first, then run the tests.
- **Expected:** A test fails.
- **Observed:** By reading: none would.
- **Impact:** A wrong order of changes, which a program shows to its user, could pass every test.
- **Recommended fix:** A case with a wrong symbol at shard 0 and marks at shards 1 and 4; order and kind assertions in the fuzz target.
- **Required verification:** The new test fails on the changed merge.

### AUD-001-ARC004 — Low — The fuzz target of files can walk 2^32 block numbers

- **Affected files:** `docs/audits/AUD-001-harnesses/fuzz/fuzz_targets/files.rs`.
- **Evidence:** The target asked for every block number a header states, up to 2^32 per file, where the survey stops at the first missing block. A header with a consistent checksum and a large length would stall a run.
- **Reproduction:** Read the loop over `read.block`.
- **Expected:** The target asks only for the blocks the survey counts.
- **Observed:** Not seen in the 200-second runs.
- **Impact:** A stalled fuzz run reported as a timeout, not a defect of the crate.
- **Recommended fix:** Loop over the blocks the survey counts.
- **Required verification:** The changed loop.

### AUD-001-API005 — Low — A list of changes cannot say whether it is locked, and two costs of protected pages go unnamed

- **Affected files:** `src/correct/changes.rs`, `src/buffer.rs`, `docs/TECHNICAL.md`.
- **Evidence:** `Changes` had no `is_locked`. On Linux a child made by `fork` reads zeros from every buffer, and buffers draw on the lock limit the program's own secrets need: about 2,048 one-page buffers use up the default 8 MiB. The documents said neither.
- **Reproduction:** Read `Changes` and the section Secrets in memory.
- **Expected:** A list says what a buffer says, and the documents name both effects.
- **Observed:** Neither.
- **Impact:** A program that forks or locks secrets of its own meets them without warning.
- **Recommended fix:** Add `Changes::is_locked`; name both effects.
- **Required verification:** The method and the documents.

### AUD-001-BLD002 — Low — The protection crate is pinned to a commit above `fixup!` commits

- **Affected files:** `Cargo.toml`.
- **Evidence:** The pinned commit of `secret-protection-core` follows three `fixup!` commits. If that history is regrouped, the pin names a commit no branch holds.
- **Reproduction:** `git log` of the protection crate up to the pinned commit.
- **Expected:** A pin that stays reachable.
- **Observed:** The pinned commit is on the published main branch.
- **Impact:** A future regrouping of the other repository would break the build until the pin is moved.
- **Recommended fix:** Pin after the regrouping, or to a tag.
- **Required verification:** None while the history stands.

## Observations

- **AUD-001-SEC001, Words of data on the stack are not wiped.** The scaling kernel pads the last bytes of a shard into an array of eight bytes on the stack, and a change read from a list is a plain value. Neither is wiped. The documents leave the stack to the program, which can run a call on a protected stack.
- **AUD-001-SEC002, The short lists of a search lie in the allocator's memory.** The recurrences, the syndromes of one column and the errors of the decoder, a few elements per spare shard, are vectors of two-byte elements. They are wiped when the decoder is dropped and are not in protected pages, which hold bytes. The documents say so.
- **AUD-001-API001, A set of tens of thousands of shards made in one call can run out of mappings.** With `protect` every shard returned is a mapping of its own with two guard pages. The call answers `CodeError::Memory` then; the documents name the limit and the way round it, `Sources::build` into one buffer of the program's.
- **AUD-001-API006, The owned results can be neither copied nor made by a program.** `Buffer` has no public constructor and no `Clone`; `Plan` and `Rebuilt` are no longer `Clone`; the `Zeroizing` re-export is gone; `CodeError` gained a variant and has no `non_exhaustive`. A copy of a result would be a second place for data; a program that wants protected memory of its own has `protect::WorkArea` and `protect::Secret`. The crate has no release yet.

## Limitations

- Only Linux for x86-64 ran at the reviewed commit. The tests on Linux for AArch64, macOS and Windows run in CI from the fix commit on.
- The fuzz targets ran 200 seconds each: enough to pass the checksums of whole sets through structured inputs, not a long campaign.
- Running time was not measured against the bytes of shards; that no branch or table entry depends on them was read in the code.
- Miri ran the unit tests of the buffer and of the list of changes with the allocator's memory; the protected pages are system calls, which it does not run.
- This is a review of code and tests, not a certification of the code.
