### Findings

#### AUD-007-BLD001 — Medium — The reviewed commit fails the formatting gate required by tagged releases

- **Category:** BLD.
- **Severity:** medium.
- **Status:** open at the reviewed commit.
- **Release blocking:** true; the mandatory tagged CI formatting gate fails.
- **Affected files and builds:** `src/correct.rs:465`, `src/file/set/vote.rs:352`, `.github/workflows/ci.yml:32-33`.
- **Reproduction:** At b16c64f, run cargo fmt --check. The retained fix-fmt run returned 1. Without checking out another tree, compare git show b16c64f:src/correct.rs with the same stream formatted by Rust 1.99.1 rustfmt --edition 2024 --emit stdout; diff -u returns 1.
- **Expected behavior:** The committed source passes the mandatory formatting gate before CI permits packaging and attestation.
- **Observed behavior:** The fold closure and the is_some_and expression need Rustfmt changes. The committed source lacks them. The current working tree contains precisely those formatting corrections and passes cargo fmt --check, but those bytes are not part of b16c64f.
- **Impact:** A tag at this commit fails CI and cannot reach the ordinary package job. This is a build failure, not a demonstrated runtime or memory-safety defect.
- **Evidence:** AUD-006-evidence/fix-fmt.command.json and fix-fmt.log (local, exit 1); AUD-007-evidence/committed-format-diff.log (local, exit 1, SHA-256 fc21a82f402f738cf2a5403bfb3de58b54f92e924320e0a394bf9f07dc617fb2); current-format.log (local, exit 0).
- **Recommended fix:** Include the existing formatting corrections in a successor commit. Preserve the reviewed commit in history.
- **Required verification:** cargo fmt --check must pass on the exact successor commit and the tagged CI workflow must consume that commit.

#### AUD-007-BLD002 — Low — The tagged release pipeline does not enforce the required timing probe

- **Category:** BLD.
- **Severity:** low.
- **Status:** open at the reviewed commit.
- **Release blocking:** false; bounded finding; no current production security failure established.
- **Affected files and builds:** `.github/workflows/release.yml:17-21`, `.github/workflows/ci.yml:26-80`, `AGENTS.md:33-35`.
- **Reproduction:** Read every run step reachable from release.yml jobs.ci and jobs.package. None builds or runs docs/audits/AUD-006-harnesses/timing, and no step inspects field arithmetic assembly.
- **Expected behavior:** A release pipeline described as including the new timing check actually runs that check and stops packaging on failure.
- **Observed behavior:** workflow_call and needs: ci correctly enforce existing CI checks. The timing requirement was added only to the manual instructions in AGENTS.md; the callable CI contains formatting, clippy, normal tests and rustdoc.
- **Impact:** The automatic release path can attest a future timing regression that passes functional tests. A manual timing preflight can still detect it; this finding does not claim that the current arithmetic fix fails or that no manual check occurs.
- **Evidence:** Static review of both complete workflows at the target commit; separate reviewer challenge. The fresh timing run passes, which does not supply an automated future gate.
- **Recommended fix:** Add a required release job that builds the timing harness with --locked --release, runs its timing binary, and gates package on its success. State the fields and compiler configurations covered.
- **Required verification:** Review the job dependency graph; demonstrate that a deliberately failing timing check prevents package/attest. Cover multiplication and inversion separately where the guarantee requires them.

#### AUD-007-BLD003 — Low — Several new oracle probes report mismatches without failing the command

- **Category:** BLD.
- **Severity:** low.
- **Status:** open at the reviewed commit.
- **Release blocking:** false; bounded finding; no current production security failure established.
- **Affected files and builds:** `docs/audits/AUD-006-harnesses/codes/src/bin/fields.rs:119-236`, `docs/audits/AUD-006-harnesses/codes/src/bin/decode.rs:206-282`, `docs/audits/AUD-006-harnesses/codes/src/bin/cyclic.rs:298-301`, `docs/audits/AUD-006-harnesses/codes/src/bin/apply_cross.rs:25-50`, `docs/audits/AUD-006-harnesses/codes/src/bin/mhfe.rs:171-182`, `docs/audits/AUD-006-harnesses/README.md:56-58`.
- **Reproduction:** Trace the mismatch counters to each main function exit. fields prints disagreements/bad_products/bad_inverses/bad_slow and boundary errors without checking them; decode prints and then shadows its tallies; cyclic prints total.bad and returns. Most apply_cross observations are only printed. The two unexpected non-Changes repair-plan branches in mhfe print NOT REPAIRED without calling fail().
- **Expected behavior:** As the harness README promises, any oracle disagreement makes the relevant command exit nonzero.
- **Observed behavior:** These mismatch paths reach a successful return unless a separate assertion happens to fail. Other mhfe mismatch paths already call fail()/finish(); this finding is limited to the unchecked paths.
- **Impact:** An automated rerun that checks only exit status can accept incorrect arithmetic, decoding or plan binding. Reviewing printed counters remains possible. No actual production oracle disagreement was demonstrated in this audit.
- **Evidence:** Complete source review of the new probes and an independent challenge. This is source-level control-flow evidence; no modified production implementation was executed to simulate a mismatch.
- **Recommended fix:** Accumulate all mismatch counters and fail once at the end, or assert each required result and unchanged-output condition. Treat equivalent-code positive controls separately from negative cases.
- **Required verification:** Give each probe a deterministic negative control that produces a mismatch and must exit nonzero, then rerun the unchanged positive oracle cases.

### Informational observations and recommendations

- The fresh holders measurement at 100,000 blocks gives 3.4 ns/step for two alternating holders versus 1.1 for stable holders; three alternating holders give 2.1 versus 0.9. These are diagnostic measurements, not a fixed performance guarantee. Fresh stateful assertions separately check correctness.
- Timing: GF(2^11) median zero/random 2615/2609 ns, ratio 1.00; Binary GF(2^10) 3178/3176 ns, ratio 1.00. 41 interleaved rounds over 2048 words; acceptance uses median ratio 0.8 through 1.25. The observed Binary per-round maximum 1.28 is retained, not suppressed.
- Assembly review covers Field::multiply and Field::inverse in both release library and LTO executable, including the gf256 inverse helper. Conditional branches select public field variants/degree or fixed loop bounds; the GF65536 inverse failure is the documented zero case. No operand-indexed memory table was found in those functions.

- The library README convention calls for one documentation-index link and no contents table for a short README. AUD-006-DOC005 is withdrawn as an inconsistent requirement; the restored table and extra introduction links can be simplified in a later documentation change.

### Assessment and limitations

An independent final review checked the report pair, registry, evidence and probe documentation and found no required correction. All 54 existing AUD-001 through AUD-005 registry rows were preserved relative to the starting working tree.

The original arithmetic timing defect is verified fixed for the compiled configurations inspected here. Decoder refitting preserves results and work accounting in the new stateful probe and existing suites; its measured allocation overhead is substantially reduced. The target is not ready to tag unchanged because its mandatory formatting gate fails. The new automation and harness findings should be resolved before claiming automatic timing-regression enforcement or relying only on oracle exit statuses.

- Full review of the requested change range, not a new all-files baseline audit of unchanged repository code or every transitive dependency. Every one of the 55 changed files was assigned and reviewed; affected callers were followed beyond the diff.
- Fresh execution is Linux x86-64 with Rust 1.99.1. No ARM/macOS/Windows runtime or assembly, Miri, forced allocation failure, statistical dudect campaign, or other compiler/optimization-level sweep was performed.
- black_box is a best-effort compiler hint, not a language-level constant-time guarantee. The evidence establishes the inspected compiled configurations and the coarse regression probe; decoder error-dependent timing remains documented.
- Retained proof/fuzz/fast-gate logs were hash-validated and their source diff reconstructed; they were not rerun. The historical runner lacks a separate post-command source fingerprint for every run.
- The concurrent fix-coverage run had no completed JSON and command record when the report was prepared. No new line-coverage percentage is claimed; the existing 98.23% is explicitly historical.
- No release was made, signed or published. v0.1.1 artifact bytes, attestation and crates.io checksum remain unverified. Only read-only remote queries were performed.
- The original vulnerable whole checkout was not rebuilt. Existing baseline evidence was retained; no second working tree or project copy was created for this audit.
- Independent reviewers were AI reviewers with separate scopes and a separate combined finding challenge; this is not an independent human security audit or proof of absence of defects.
